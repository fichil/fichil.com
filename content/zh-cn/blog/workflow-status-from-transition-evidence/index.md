一个运营看板开始把订单提前推进到后续阶段：收货刚完成，页面就显示卸货或检验；订单已经发运，报表却仍把它标成较早的核对阶段。真实业务交易还在继续，状态报表描述的操作边界已经偏离现场。

故障同时涉及读写两端。报表接受了流转表中的全部记录，其中包括没有开始时间的行，以及为未来阶段提前生成的占位记录。另一个业务入口在当前阶段结束时立即创建下一阶段里程碑。两类信号进入同一条排序链后，“取最新一条”无法稳定说明哪项工作已经开始。

最终修复把当前状态改成一项可复核的推导结果：先分类流转证据，再统一历史编码，只在事件缺失时使用有限的业务补偿，同时把里程碑写入移到真实转换位置。所有报表视图都改为消费同一个解析结果。

## 对齐三类证据，先复现分歧

排查先对同一批订单执行只读比较，范围包括：

- 报表使用的流转事件；
- 收货、检验与发运领域拥有的业务状态和时间；
- 明细、汇总及异常查询最终显示的阶段。

比较结果暴露出三种数据形态。

第一种事件只有节点编码，开始时间为空。原查询按时间倒序选择事件时，这类行可能排在有效记录前面，使报表展示一个没有可观察开始时间的阶段。

第二种是检验占位。记录时间与收货结束完全相同，业务检验状态仍处于等待。沿源码追踪后确认，收货完成入口为了衔接后续流程提前写入了检验开始；这项便利写入被报表当成了真实操作证据。

第三种来自历史出库编码。旧编码原本表示发运活动，新报表却按另一套含义把它解释为核对阶段。原始值存在，时间顺序也正确，语义映射仍然得出了错误状态。

这三种情况需要分别处理。过滤空时间无法修复旧编码，重新映射编码也不能区分真实检验与占位检验。单纯选择“最大节点”或“最新事件”掩盖了多份不同契约。

## 建立唯一的阶段解析关系

修复后的查询采用一条共享的概念管线：

```text
原始事件
  -> 有可观察开始时间的事件
  -> 排除已知占位转换
  -> 统一历史编码
  -> 有边界的业务证据补偿
  -> 唯一当前阶段
```

开始时间为空的事件不再参与当前阶段排序。历史审计可以继续保留这条记录，但它不能证明某项操作已经启动。

已知检验占位只有同时满足三个条件才会被排除：时间等于上一阶段结束、检验业务仍在等待、没有独立检验活动。真实检验开始不会被过滤，因为对应业务状态或工作记录能够提供旁证。

历史节点编码在选择当前阶段前先映射到现行模型。映射规则明确写出并单独验证，不依赖编码数值大小来推断流程先后。

有效里程碑缺失时，解析器只使用少量由业务领域负责的信号补偿。已完成的收货时间可以支持收货阶段，检验中状态可以支持检验阶段，发运时间可以支持发运阶段。如果领域本应提供更具体时间，解析器不会退回普通更新时间来制造精确度假象。

最终关系同时给出阶段、开始时间、结束时间和证据类型。明细、页签筛选、停留时间、标准时效比较及异常汇总都从这份关系取数。若继续保留多份状态判断树，后续修复很容易只覆盖部分视图。

## 在真实业务转换时记录里程碑

查询兼容可以解释历史数据，未来事件还需要正确的生产位置。

收货完成不再创建检验开始。新的检验里程碑由能够证明该阶段已经启动的操作写入，例如检验任务成功创建，或业务状态确认进入检验中。各入口都在自身业务更新成功后调用同一个幂等记录器。

记录器保留第一次有效开始。重复回调不会新增记录，也不会重置时间。若遇到与上一阶段结束时间相同的旧占位，真实开始可以修正该记录。结束通知先到、开始记录缺失时，记录器会补出开始和结束同一时刻的有限零时长事件，避免已完成阶段继续缺少可解析记录。

监控写入还要尊重业务事务边界。若追加报表证据失败，系统留下可对账错误，同时保持已经成功的收货或检验结果。这样不会让观测能力修复制造新的业务中断。代价同样明确：业务成功而事件写入失败是一种允许出现的降级状态，对账任务仍需持续发现并处理它。

## 同时验证语义、构建和报表对账

验证覆盖静态结构、应用构建和数据库结果。

所有修改后的查询映射先完成结构解析。随后使用遗留项目要求的兼容 Java 运行时构建全部受影响模块，确认共享记录器及各调用方在模块边界上仍能正常编译。

只读数据库回归覆盖以下场景：

| 场景 | 预期解析阶段 |
| --- | --- |
| 上一阶段完成、存在下一阶段占位、业务仍在等待 | 上一阶段 |
| 检验业务已经开始、有效检验事件缺失 | 检验 |
| 存在真实检验开始记录 | 检验 |
| 旧出库编码的含义为发运 | 发运 |
| 已有发运证据、缺少新发运事件 | 发运 |

同一组样本还分别进入明细与汇总查询。按节点筛选时，汇总数量与对应明细一致；按异常筛选时，两边同样一致。这说明停留时间和阈值判断已经使用统一解析阶段，没有继续走旧状态分支。

验证没有修改历史事件。它证明新的读模型能够解释已观察到的空时间、占位与历史编码，也确认未来事件会在更接近真实操作开始的位置生成。

## 适用边界

业务证据补偿属于兼容机制。如果来源状态或时间本身延迟、错误，推导阶段仍可能失真。每项补偿都应明确数据归属、字段含义和对账方式。

本次只读回归覆盖了已知故障形态的数据库快照，没有模拟全部并发写入顺序，也没有覆盖所有延迟外部回调。生产监控仍应持续检查两类信号：业务已进入新状态但缺少有效事件，以及明细与汇总分区数量不一致。

可复用的方法是把业务流程状态视为证据解析结果：只接受能证明转换发生的事件，显式统一历史含义，以有限领域数据补偿缺失记录，在真实操作处幂等写入里程碑，并让全部报表投影消费同一份已解析状态。
