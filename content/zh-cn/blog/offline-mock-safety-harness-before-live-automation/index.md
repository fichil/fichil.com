桌面消息自动化在设计图上可能只有两个步骤：观察会话，执行动作。风险集中在两者的连接处。当前目标可能切换，输入框可能出现草稿，适配器也可能在尝试提交后丢失确认信号。

一项已完成的实现先建立了范围很小的离线里程碑，使用合成消息、Mock 适配器、可信策略和持久化动作状态。三十六项单元测试在禁止创建网络 socket 的条件下全部通过。真实客户端、模型 API 和自动回复生成器均未参与。

这个范围决定了结论的边界。证据覆盖组装后的观察与动作流程；架构图里规划的生成服务和对话记忆，仍需后续实现与测试。

## 让最小完整流程可以执行

实现划分了五类职责：

| 部分 | 已实现的职责 |
|---|---|
| 领域模型 | 描述目标、消息、动作请求、观察状态和结果 |
| Mock 适配器 | 提供合成观察，模拟提交及确认 |
| 策略 | 检查可信目标、运行模式、操作类型和文本长度 |
| 状态存储 | 在 SQLite 中记录事件去重及动作身份、结果 |
| 应用 | 编排检查、暂停、动作尝试与核验 |

这里的状态存储保存运行状态，不承担对话记忆职责。模型提供方和回复生成留待后续里程碑。

轮询与执行是两个分离的应用操作。轮询会过滤重复事件和账号自己的消息，但不会安排自动回复。执行动作需要单独构造请求。测试因此能够在明确的位置检查授权，无需引入模型或真实会话。

## 消息内容不能修改授权规则

可信配置声明目标白名单和运行模式，适配器报告连接状态、目标身份以及是否存在草稿。收到的文本保持为消息数据。

一项测试输入了要求放开所有会话、切换实时模式和执行命令的文本。运行模式与目标白名单保持不变，应用没有把这段文本当作动作许可。

原型提供三种模式：

- **Read-only，只读**：默认模式。可以轮询允许范围内的合成事件，动作请求会被拒绝。
- **Dry-run，预演**：需要显式选择。执行策略和当前目标检查，不调用提交，也不占用动作请求 ID。
- **Mock，模拟执行**：需要显式选择。使用内置模拟适配器演练内存中的提交与确认流程；没有实时执行模式。

CLI 使用固定的合成事件和动作请求。显式 dry-run 返回零次 Mock 提交，证明了存在合格事件时模式约束仍然生效。这组结果不构成空输入启动路径的验证证据。

## 同时检查动作边界与返回结果

预检查会拒绝未获授权或不匹配的目标、已有草稿、连接中断以及身份不确定。测试同时断言返回原因和提交调用数为零。

允许模拟执行时，应用会先持久化动作占用记录，再调用适配器。持久化之后还会重新检查目标、草稿和暂停状态。Mock 适配器在提交边界再次检查目标与草稿。测试在两次检查之间改变观察状态，验证后一次检查仍能阻止动作。

这种顺序提供了可操作的测试方法：安排状态变化，运行应用，再检查调用次数和存储结果。单独看到一个表示拒绝的返回值，无法证明更早的步骤没有产生副作用。

## 记录不确定结果，避免擅自重试

动作结果区分已尝试、模拟 UI 确认、明确失败和未知。测试注入提交超时或不完整确认后，应用会记录未知结果。

状态库保存动作身份与结果。同一请求再次执行时会返回已有记录，不再提交。测试还重新打开 SQLite 状态库，确认未知结果能够跨重启保留，并阻止再次提交。同一请求 ID 搭配不同内容或目标也会被拒绝。

这些验证适用于受测的请求身份和本地状态库。事件去重另有边界：事件交给调用方之前就会记为已见，所以本里程碑不保证下游已经成功消费消息。清空状态库也会删除抑制重放所需的历史。

## 准确说明测试证明了什么

测试套件覆盖目标与草稿保护、重复和自发消息过滤、暂停、断线、注入异常、状态库重开以及 CLI 模式。预检查拒绝场景断言适配器提交数为零；本阶段没有实现生成服务，因此也没有生成服务调用次数断言。

超时测试在指定位置抛出 `TimeoutError`，验证应用收到这类异常后的处理分支。同步原型没有为真实 UI 调用设置硬截止时间，也没有实现取消机制。未来真实适配器仍需补齐这些能力。

这组证据也不覆盖真实客户端兼容性和收件人送达。未来即使获得 UI 确认，也需要与对方实际收到消息的证据分开记录。真实账号、真实写入和把会话数据传给模型服务，都需要各自范围明确的授权测试。

可复用的经验是先建立可执行的安全边界，再连接外部系统，并让完成结论严格对应已有证据。Mock 适配器能够提前暴露策略与执行顺序缺陷；尚未实现或未实际运行的集成，仍需独立验证。
